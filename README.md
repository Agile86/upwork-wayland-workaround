# Upwork Wayland Bridge for GNOME

A workaround to run Upwork's time tracking application on GNOME Wayland sessions without X11 support.

## Problem

Modern GNOME installations are moving to pure Wayland sessions, with some distributions (like Fedora 43+) completely removing X11 session support. Upwork's desktop application requires X11 for screenshot functionality and will refuse to run on Wayland, displaying an error: "Upwork screenshots are only available on Xorg sessions."

## Solution

This bridge consists of two components:

1. **screenshot.py** - A D-Bus service that emulates GNOME Shell's screenshot API, using `grim` to capture screenshots on Wayland
2. **upwork-launcher.sh** - A launcher script that tricks Upwork into thinking it's running on X11 while actually using Wayland

## Requirements

- GNOME desktop environment running on Wayland
- Python 3.5+
- Upwork desktop application
- Required packages:
  - `grim` - Wayland screenshot utility
  - `swayidle` - For activity tracking (optional but recommended)
  - `dbus-next` - Python D-Bus library

## Compatibility

Tested and working on:
- Fedora 43+ (GNOME on Wayland)
- Ubuntu 24.04+ (GNOME on Wayland)
- Arch Linux (GNOME on Wayland)
- Any Linux distribution running GNOME on pure Wayland

## Installation

### 1. Clone the repository
```bash
git clone https://github.com/yourusername/upwork-wayland-bridge.git
cd upwork-wayland-bridge
```

### 2. Install dependencies

**Fedora/RHEL:**
```bash
sudo dnf install grim swayidle
pip3 install --user dbus-next
```

**Ubuntu/Debian:**
```bash
sudo apt install grim swayidle
pip3 install --user dbus-next
```

**Arch Linux:**
```bash
sudo pacman -S grim swayidle
pip3 install --user dbus-next
```

### 3. Make scripts executable
```bash
chmod +x screenshot.py
chmod +x upwork-launcher.sh
```

## Usage

### Quick Start

Simply run the launcher script from the project directory:
```bash
./upwork-launcher.sh
```

The launcher will automatically:
- Start the screenshot bridge if it is needed and not already running
- Launch Upwork with the proper environment variables
- Enable screenshot functionality

If `org.gnome.Shell.Screenshot` is already owned on the session bus (as on
GNOME Shell 50, where `gnome-shell` owns it), the launcher skips the bridge and
prints a note. On that setup the X11 environment override alone was enough for
screenshots to work.

### Make it permanent

#### Option 1: Add to PATH

Add to your `~/.zshrc` or `~/.bashrc`:
```bash
export PATH="$HOME/path/to/upwork-wayland-bridge:$PATH"
```

Then reload your shell:
```bash
source ~/.zshrc  # or source ~/.bashrc
```

#### Option 2: Create an alias

Add to your `~/.zshrc` or `~/.bashrc`:
```bash
alias upwork='~/path/to/upwork-wayland-bridge/upwork-launcher.sh'
```

#### Option 3: Install desktop launcher
```bash
./install.sh
```

This generates `~/.local/share/applications/upwork-fixed.desktop`, shown in the GNOME app list as **Upwork - fixed**, pointing to the launcher. It keeps the Upwork icon and updates the desktop database. The stock **Upwork** entry from `/usr/share/applications/upwork.desktop` is left untouched, so you can tell the two apart: always start **Upwork - fixed**. `upwork://` links also open through the fixed entry.

If an earlier version of `install.sh` created `~/.local/share/applications/upwork.desktop`, re-running the installer removes it. An existing `upwork-fixed.desktop` that was not generated by `install.sh` is backed up to `upwork-fixed.desktop.bak` first.

Upwork is single-instance. If a copy started from the stock entry is still running (including the tray icon), quit it completely before launching again, or the new launch will exit and the old instance will keep its old environment.

To uninstall the launcher:
```bash
rm ~/.local/share/applications/upwork-fixed.desktop
```

## Screenshots on GNOME Wayland: the patched copy

On newer GNOME (tested on GNOME Shell 50 / Ubuntu) `gnome-shell` owns the
Screenshot D-Bus name, so the bridge is not needed. The remaining problem is
inside Upwork: it asks its native module `isWayland()` on every screenshot. The
native module answers `true` on a Wayland session, so after the first
screenshot Upwork blanks all later ones and shows "Wayland not supported,
please switch to Xorg". Unsetting `WAYLAND_DISPLAY` does not help, because the
native check calls `wl_display_connect(NULL)`, which falls back to
`$XDG_RUNTIME_DIR/wayland-0`.

`patch-upwork.sh` works around this without touching `/opt/Upwork`: it makes a
private copy in `~/.local/share/upwork-wayland-workaround/Upwork` and patches
5 bytes of `uta_native.node` so `IsWayland()` always returns false. Upwork keeps
capturing through the XDG screenshot portal. `upwork-launcher.sh` runs this copy
automatically and rebuilds it when the installed Upwork changes. If the patch
does not apply (unknown Upwork build) the launcher falls back to the stock
install. Set `UPWORK_NO_PATCH=1` to always run the stock install.

Two one-time steps are needed for the copy:

1. **Sandbox helper.** Chromium aborts unless `chrome-sandbox` is root-owned with
   mode 4755, which a user-made copy cannot set itself. The launcher prints the
   exact command when it is needed:
   ```bash
   sudo chown root:root ~/.local/share/upwork-wayland-workaround/Upwork/chrome-sandbox
   sudo chmod 4755 ~/.local/share/upwork-wayland-workaround/Upwork/chrome-sandbox
   ```
   Repeat it after the copy is rebuilt (for example when Upwork is updated).
2. **Portal permission.** The screenshot portal identifies the app by its desktop
   entry name. The first screenshot from **Upwork - fixed** needs permission for
   the app id `upwork-fixed`; Upwork runs in the background, so the portal cannot
   show its dialog and the screenshot fails ("Failed to take screenshot").
   Grant it once:
   ```bash
   gdbus call --session --dest org.freedesktop.impl.portal.PermissionStore \
     --object-path /org/freedesktop/impl/portal/PermissionStore \
     --method org.freedesktop.impl.portal.PermissionStore.SetPermission \
     screenshot true screenshot upwork-fixed "['yes']"
   ```

This runs a modified copy of Upwork, which Upwork does not support; see the
disclaimer below.

## How It Works

1. **screenshot.py** creates a D-Bus service that implements the `org.gnome.Shell.Screenshot` interface
2. When Upwork requests a screenshot via D-Bus, the bridge uses `grim` to capture the screen
3. **upwork-launcher.sh** sets environment variables (`XDG_SESSION_TYPE=x11`) to make Upwork believe it's running on X11
4. Upwork operates normally, taking screenshots through the bridge without knowing it's actually on Wayland

## Troubleshooting

### Screenshots not working

Check if the bridge is running:
```bash
pgrep -af screenshot.py
```

Check for errors:
```bash
python3 screenshot.py
# Look for error messages in the output
```

### "Wayland not supported" after the first screenshot

Make sure Upwork runs from the patched copy (quit it completely first, including the tray icon):
```bash
readlink /proc/$(pgrep -xo upwork)/exe
# expected: ~/.local/share/upwork-wayland-workaround/Upwork/upwork
```
If it shows `/opt/Upwork/upwork`, run `./upwork-launcher.sh` in a terminal and read its warnings (most often the one-time `chrome-sandbox` step above).

### "Failed to take screenshot"

Check the journal for `Only the focused app is allowed to show a system access dialog`:
```bash
journalctl --user -b | grep -i 'access dialog'
```
That means the portal permission for the app id is missing; see step 2 above.

### Upwork still complains about Xorg

Make sure you're launching Upwork via the launcher script, not directly. The environment variables must be set. Also make sure no older Upwork instance is still running (check the tray icon); a running instance keeps the environment it was started with.

### Bridge fails to start

Ensure `grim` is installed and working:
```bash
grim /tmp/test.png
# Check if the screenshot was created
ls -lh /tmp/test.png
```

### Verify you're running Wayland

Check your current session type:
```bash
echo $XDG_SESSION_TYPE
# Should output: wayland
```

If you're already on X11, this bridge is not needed.

## Limitations

- Window-specific screenshots fall back to full screen capture (Wayland security restriction)
- Designed specifically for GNOME on Wayland; other Wayland compositors (Sway, KDE) may require adjustments
- Idle time tracking requires `swayidle`

### FAQ

**Q: Will this work on KDE Plasma Wayland?**  
A: This is designed for GNOME. KDE uses different D-Bus interfaces, so modifications would be needed.

**Q: Is this safe to use?**  
A: Yes, it only provides a screenshot interface. It doesn't modify Upwork or bypass any security features.

**Q: Can I use this with other applications that require X11 screenshots?**  
A: Potentially yes, if they use the same GNOME Shell screenshot D-Bus interface.

**Q: Do I need to run this every time I start my computer?**  
A: If you set it up via the desktop launcher (Option 3), it will start automatically when you launch Upwork from your application menu.
